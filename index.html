CSC 139 · OPERATING SYSTEMS · C + PTHREADS

Concurrent Fetch-on-Miss Cache

ConcurrencyCachingOperating Systems

A multithreaded, read-through cache in C sitting in front of a slow backing store. Many client threads hit it at once, and it has to stay correct through cache stampedes, failed fetches, a throttled backend and mid-flight shutdown. It's the same problem a CDN edge or a Redis-fronted API solves, built from mutexes and condition variables.

1 fetchper key, however many waiters
≤ Nconcurrent backing fetches
CLOCK& FIFO eviction
8trace scenarios incl. stampede
  • Single-flight request coalescing: the first miss creates an in-flight record; later requests for the same key wait on its condition variable instead of hitting the backend again.
  • In-flight records are reference-counted across pthread_cond_wait, so waiters stay safe even when the fetch fails or the cache shuts down underneath them.
  • Backpressure: at most N concurrent backing fetches, with excess misses parked on a throttle condition variable. Throttle violations are tracked and tested.
  • Graceful shutdown broadcasts to every waiter and aborts outstanding requests cleanly instead of deadlocking.
  • Built on my variable-size memory pool (below), with a hash index for O(1) lookups and evict-on-fetch when the pool is full.

From the Kernel Up

The low-level coursework isn't a detour from backend engineering. It's the same set of problems, a few layers down. Here's where each idea shows up again.

pipes · FIFOs
↓
Message queues & streams

A pipe is a bounded byte stream between a producer and a consumer. Redis Streams with consumer groups is the same idea, durable and networked, and it carries telemetry in my rollout platform.

fork · exec · wait
↓
Supervision & orchestration

Launching a child, watching it and reaping its exit status is what container runtimes and orchestrators do at scale. It's also how a controller decides whether a deployment is healthy.

signals
↓
Graceful shutdown

Catching SIGINT/SIGTERM and cleaning up comes back as draining connections, flushing batch writers and finishing in-flight work before a service exits.

ACKs · timeouts · retransmit
↓
At-least-once delivery

Reliable UDP taught me that retries create duplicates. That's why idempotency keys, consumer acknowledgements and dedup logic matter in distributed APIs.

synchronized · races
↓
Concurrent services

Guarding shared transfer state in Java led straight to per-tenant goroutines in Go, and to writing explicit race-condition tests instead of hoping.

in-flight records · cond vars
↓
Request coalescing

My OS cache lets one thread fetch a missing key while the rest wait on it. That's Go's singleflight, CDN request collapsing and cache-stampede protection in front of a database.

fetch throttle · waiting threads
↓
Backpressure & rate limits

Capping concurrent backing fetches and parking the rest is connection-pool limits, bulkheads and rate limiting: protecting a slow dependency from your own traffic.

allocators · CLOCK eviction
↓
Caching layers

Writing first/best-fit, coalescing and second-chance eviction by hand explains Redis eviction policies, memory fragmentation and why cache sizing is a design decision.
